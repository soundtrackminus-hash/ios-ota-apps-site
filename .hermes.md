# Правила работы над проектом (Hermes)

Аня — владелица проекта. Правила обязательны, если Аня не сказала иного прямо.

## Не заниматься самодеятельностью

- **Сначала план, потом действие.** Любая задача больше одной мелочи начинается с
  короткого плана: что делаю, зачем, что может сломаться. Дальше — жду ответа Ани.
  Планы, которые Аня не подтвердила, не выполнять «по пути».
- **Делать ровно то, что попросили.** Не рефакторить «заодно», не переписывать
  работающие части, не менять стек, зависимости, нейминг, структуру каталогов и
  формат данных без отдельной просьбы.
- **Не создавать лишнего.** Новые файлы, скрипты, конфиги, зависимости, дубли —
  только если это нужно для задачи и Аня согласилась. Миграции «на будущее»,
  «улучшения», «причесывание» — не делать.
- **Не удалять и не перезаписывать** существующие файлы, данные, кэш, конфиги
  без явного «да». Перезапись файла = удаление старого содержимого, тоже
  спрашивать.
- **Не коммитить и не пушить**, пока Аня не попросит. `git status` смотреть
  можно, коммиты — нельзя.
- **Сомневаешься — спроси.** Один вопрос дешевле, чем откат. Ответ «делай как
  считаешь правильным» — это согласие только на то, что было перечислено.

## Как отчитываться

Коротко: что изменилось, что проверено, что осталось. Без пересказа процесса.

## Специфика этого репозитория

- Сайт раздаёт IPA с GitHub releases: `app-data.js` →
  `soundtrackminus-hash/ios-ota-apps-site/releases/...`. Локальные копии `.ipa`
  сайту не нужны.
- Источник IPA — Google Drive. Скрипты синка берут их в staging
  `/root/.hermes/cache/scratch/ios-apps*`.
- **Обрабатывать по одному приложению за раз**, скачанное — удалять после
  обработки. Кэш не копить: 21 ГБ IPA посадили диск в 0 байт.
